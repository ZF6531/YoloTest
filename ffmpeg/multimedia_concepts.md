# 音视频领域基本概念详解

本文档系统梳理音视频处理中的核心概念，帮助建立从信号采集到播放的完整知识图谱。

---

## 1. 编解码器（Codec）

### 定义
**Codec** 是 **COder-DECoder**（编码器-解码器）的缩写，负责将原始音视频信号压缩为数字码流（编码），或从码流还原为原始信号（解码）。

### 为什么需要编解码
原始音视频数据量极大。例如：
- 1080p@60fps 的未压缩视频，每秒约 **3 Gbps**
- CD 音质的未压缩音频，每秒约 **1.4 Mbps**

通过编解码器进行有损/无损压缩，才能在存储和传输中实用化。

### 常见视频编解码器

| 编解码器 | 特点 | 典型应用 |
|----------|------|----------|
| **H.264/AVC** | 兼容性最好，压缩效率适中 | 网络视频、蓝光、直播 |
| **H.265/HEVC** | 比 H.264 节省约 50% 码率 | 4K/8K 视频、HDR |
| **AV1** | 开源免版税，压缩效率优于 HEVC | YouTube、Netflix、WebRTC |
| **VP9** | Google 主推，开源免版税 | YouTube、WebM |
| **MPEG-2** | 历史悠久，专利已到期 | 传统数字电视、DVD |

### 常见音频编解码器

| 编解码器 | 特点 | 典型应用 |
|----------|------|----------|
| **AAC** | 效率高于 MP3，广泛支持 | 流媒体、广播、移动设备 |
| **MP3** | 历史最悠久的有损音频格式 | 音乐存储、兼容性场景 |
| **Opus** | 低延迟，全频段高效 | VoIP、WebRTC、游戏语音 |
| **FLAC** | 无损压缩，可完全还原 | 音乐发烧友、母带存储 |
| **PCM** | 原始未压缩音频 | 专业音频制作、CD |

## 2. 媒体封装与解封装（Mux / Demux）

### 定义
- **封装（Mux / Multiplex）**：将视频流、音频流、字幕流等按照特定格式打包到一个文件中
- **解封装（Demux / Demultiplex）**：从封装文件中分离出各个独立流

### 容器格式 vs 编解码器
这是初学者最容易混淆的一对概念：

> **容器格式**（如 MP4）是"盒子"，**编解码器**（如 H.264）是"盒子里的内容"。

同一个容器可以装不同编解码器的数据：
- MP4 容器 + H.264 视频 + AAC 音频
- MP4 容器 + H.265 视频 + AAC 音频
- MKV 容器 + AV1 视频 + FLAC 音频 + ASS 字幕

### 常见容器格式

| 格式 | 特点 | 支持能力 |
|------|------|----------|
| **MP4** | 兼容性最强，网络友好 | H.264/H.265/AV1 + AAC/MP3 |
| **MKV** | 开源灵活，功能丰富 | 几乎所有编解码器和字幕格式 |
| **TS** | 传输流，容错性强 | 数字电视、IPTV、直播 |
| **FLV** | 简单、低延迟 | 传统 RTMP 直播 |
| **WebM** | 为 Web 优化 | VP8/VP9/AV1 + Vorbis/Opus |
| **MOV** | Apple 开发，专业编辑友好 | ProRes、高清摄像 |

## 3. 媒体流（Stream）

### 定义
一个多媒体文件内部通常包含多条**流（Stream）**，每条流对应一种媒体类型：
- **视频流（Video Stream）**：图像序列
- **音频流（Audio Stream）**：声音采样序列
- **字幕流（Subtitle Stream）**：时间同步的文本或图形
- **附件流（Attachment Stream）**：字体文件、封面图等

### 流索引（Stream Index）
在解封装时，每条流会被分配一个从 0 开始的索引号。例如：
```
Stream #0:0 -> Video (h264)
Stream #0:1 -> Audio (aac)
Stream #0:2 -> Subtitle (ass)
```

## 4. 帧（Frame）与图像基础

### 4.1 帧（Frame）
视频由一连串静止图像组成，每一张图像称为一**帧**。帧率是衡量视频流畅度的核心指标。

### 4.2 像素（Pixel）
像素是图像的最小单位。视频分辨率表示画面在水平和垂直方向上的像素数量，如 1920×1080 表示约 207 万个像素。

### 4.3 像素格式（Pixel Format）
像素格式定义了每个像素的颜色数据如何存储。

| 格式 | 说明 | 应用场景 |
|------|------|----------|
| **RGB24** | 红绿蓝三通道，每通道 8bit | 显示器、图像处理 |
| **RGBA** | RGB + Alpha 透明度通道 | 特效合成、游戏 |
| **YUV420P** | Y（亮度）+ UV（色度），色度 subsample 为 4:2:0 | 最常见的视频编码格式 |
| **NV12** | YUV420 的半平面格式，UV 交错存储 | 硬件编解码常用 |
| **YUV422P** | 色度水平方向未压缩，画质优于 420 | 广播级视频 |

#### YUV 色彩空间
- **Y**：亮度（Luma），决定图像的明暗层次
- **U/V**：色度（Chroma），决定颜色信息
- **4:2:0 subsample**：人眼对亮度更敏感，因此色度信息可以降采样，减少 50% 数据量

### 4.4 色彩空间与色域

- **色彩空间（Color Space）**：定义了颜色的数学表示方式
  - **RGB**：基于三原色，用于显示设备
  - **YUV/YCbCr**：基于亮度和色度分离，用于视频压缩

- **色域（Color Gamut）**：设备能表示的颜色范围
  - **BT.709**：高清电视标准色域
  - **BT.2020**：超高清（4K/8K）广色域标准
  - **DCI-P3**：数字电影常用色域

## 5. 音频基础概念

### 5.1 采样率（Sample Rate）
每秒对模拟声音信号采样的次数，单位 Hz。

| 采样率 | 说明 |
|--------|------|
| **8000 Hz** | 电话语音质量 |
| **44100 Hz** | CD 音质标准 |
| **48000 Hz** | 专业音频、影视制作标准 |
| **96000/192000 Hz** | 高解析音频（Hi-Res）|

> **奈奎斯特定理**：采样率必须大于信号最高频率的 2 倍才能完整还原。人耳上限约 20kHz，因此 44.1kHz 是 CD 标准。

### 5.2 采样格式（Sample Format）
每个采样点用多少位（bit）表示，以及是整数还是浮点数。

| 格式 | 说明 |
|------|------|
| **S16** | 16bit 有符号整数，CD 标准 |
| **S32** | 32bit 有符号整数，动态范围更大 |
| **FLTP** | 32bit 浮点， planer 排列 | 现代编解码器（AAC/Opus）内部常用 |
| **DBL** | 64bit 浮点 | 专业音频处理 |

### 5.3 声道与声道布局（Channel Layout）

| 布局 | 声道数 | 说明 |
|------|--------|------|
| **Mono** | 1 | 单声道 |
| **Stereo** | 2 | 立体声（左/右） |
| **5.1** | 6 | 家庭影院标准（前左/前右/中置/低音/后左/后右） |
| **7.1** | 8 | 影院级环绕声 |

### 5.4 音频码率计算
```
未压缩音频码率 = 采样率 × 采样位深 × 声道数
例如：48kHz × 16bit × 2 = 1.536 Mbps
```

## 6. 视频时序概念

### 6.1 帧率（Frame Rate, FPS）
每秒显示的帧数。

| 帧率 | 应用场景 |
|------|----------|
| **24fps** | 电影标准 |
| **25fps** | PAL 制式电视 |
| **30fps** | NTSC 制式电视 |
| **60fps** | 游戏、体育赛事、高流畅度视频 |
| **120fps+** | 慢动作回放、电竞 |

### 6.2 时间基（Time Base）
音视频处理中，时间用有理数表示，避免浮点精度误差。
- `time_base = 1/帧率` 或 `1/采样率`
- 例如：25fps 的视频，time_base 通常为 `1/25` 秒，即每帧 40ms

### 6.3 PTS 与 DTS

- **PTS（Presentation Time Stamp）**：显示时间戳，告诉播放器这帧应该何时呈现给用户
- **DTS（Decoding Time Stamp）**：解码时间戳，告诉解码器这帧应该何时被解码

对于 I/P/B 帧混合编码的视频，由于 B 帧解码顺序和显示顺序不同，**DTS ≤ PTS** 是常见现象。

## 7. 视频压缩核心概念

### 7.1 GOP（Group of Pictures）
**GOP** 是两个 I 帧之间的帧序列，是视频随机访问的基本单位。

- GOP 越小，视频越容易从任意位置开始播放（适合直播、快进快退）
- GOP 越大，压缩效率越高（适合点播、存储）

### 7.2 I 帧、P 帧、B 帧

| 帧类型 | 名称 | 压缩方式 | 特点 |
|--------|------|----------|------|
| **I 帧** | Intra-frame | 仅帧内压缩 | 独立解码，是 GOP 起点，体积最大 |
| **P 帧** | Predicted | 前向预测 | 参考前一帧，只记录变化部分 |
| **B 帧** | Bi-directional | 双向预测 | 参考前后帧，压缩率最高，解码延迟略大 |

### 7.3 量化（Quantization）
量化是有损压缩的核心步骤。它将高精度的 DCT 系数映射到低精度，丢弃人眼不敏感的高频细节。
- **量化参数（QP）越大**：丢弃信息越多，画质越低，体积越小
- **QP 越小**：保留信息越多，画质越高，体积越大

### 7.4 码率（Bitrate）
每秒传输或存储的比特数，单位 kbps / Mbps。

| 码率控制模式 | 说明 |
|--------------|------|
| **CBR（Constant Bitrate）** | 恒定码率，直播场景常用 |
| **VBR（Variable Bitrate）** | 可变码率，画面复杂时提升码率，简单时降低 |
| **CRF（Constant Rate Factor）** | 恒定质量因子，画质优先，适合本地转码 |

## 8. 滤波与处理（Filter / Processing）

### 8.1 滤波（Filter）
在音视频处理中，**滤波**指对信号进行特定运算，以达到增强、变换或提取信息的目的。

#### 视频滤波示例
| 滤镜 | 作用 |
|------|------|
| **scale** | 改变分辨率（缩放） |
| **crop** | 裁剪画面区域 |
| **overlay** | 叠加另一路视频或图片 |
| **transpose** | 旋转、翻转画面 |
| **fps** | 改变帧率 |
| **delogo** | 去除台标/水印 |

#### 音频滤波示例
| 滤镜 | 作用 |
|------|------|
| **volume** | 调整音量 |
| **atempo** | 调整播放速度（不改变音调） |
| **amix** | 多路音频混音 |
| **highpass/lowpass** | 高通/低通滤波 |
| **silencedetect** | 检测静音段落 |

### 8.2 去噪（Denoise）
去除视频或音频中的噪声，提升信噪比（SNR）。

- **视频去噪**：消除传感器热噪声、压缩块效应产生的噪点
  - 常用算法：时域滤波、空域中值滤波、BM3D、NLM（非局部均值）
- **音频去噪**：消除电流嗡嗡声、环境底噪
  - 常用算法：频谱减法、Wiener 滤波、AI 降噪

### 8.3 去块效应（Deblocking）
块效应是 DCT 变换以 8×8 或 16×16 宏块为单位编码时，在块边界产生的可见马赛克边缘。
- **去块滤波器（Deblock Filter）**：如 H.264 的 in-loop deblocking filter，在编码/解码环路内平滑块边界
- 现代编码器（H.265/AV1）使用更先进的 SAO（Sample Adaptive Offset）和 ALF（Adaptive Loop Filter）技术

### 8.4 反交错（Deinterlace）
传统电视信号采用交错扫描（先扫描奇数行，再扫描偶数行）。在液晶显示器上播放时会产生"梳状"伪影，需要通过反交错算法转换为逐行扫描。

## 9. 流媒体与网络传输概念

### 9.1 流媒体协议

| 协议 | 特点 | 应用场景 |
|------|------|----------|
| **HLS** | Apple 提出，基于 HTTP + TS 切片 | 移动端直播、点播 |
| **DASH** | 国际标准，基于 HTTP + MP4 切片 | 跨平台流媒体 |
| **RTMP** | Adobe 私有协议，低延迟 | 主播推流 |
| **RTSP/RTP** | 标准实时流传输协议 | 监控、IPTV |
| **WebRTC** | 浏览器点对点实时通信 | 视频会议、在线客服 |

### 9.2 延迟（Latency）
从信号采集到观众看到画面之间的时延。不同场景对延迟要求不同：
- **点播（VOD）**：可接受 10~30 秒延迟（利用大缓冲区保证流畅）
- **直播**：通常 3~10 秒
- **实时互动（连麦）**：要求 < 500ms，常用 WebRTC 实现

## 10. 硬件加速概念

### 10.1 为什么要硬件加速
软件编解码虽然灵活，但 CPU 占用高、功耗大。现代 GPU 和专用芯片内置了视频编解码单元，可显著降低 CPU 负载和能耗。

### 10.2 常见硬件加速接口

| 接口/技术 | 平台 | 说明 |
|-----------|------|------|
| **NVENC/NVDEC** | NVIDIA GPU | 高性能硬件编解码 |
| **Quick Sync** | Intel CPU/iGPU | 集成显卡硬件加速 |
| **VAAPI** | Linux | 开源视频加速接口 |
| **VideoToolbox** | macOS/iOS | Apple 原生硬件加速 |
| **MediaCodec** | Android | 移动设备标准硬件接口 |
| **DXVA/D3D11VA** | Windows | DirectX 视频加速 |

## 11. 元数据（Metadata）

多媒体文件中附带的描述性信息：
- **标题、作者、专辑**：ID3、MP4 的 moov/udta 原子
- **旋转角度**：手机拍摄时常带 90° 旋转标记
- **色彩信息**：color_range、color_primaries、transfer_characteristics
- **章节信息（Chapters）**：DVD、MKV 中的分段标记
